# Автоматизация обработки заказов для Foppa GmbH

Проект по дисциплине NLP & Web Analytics, Free University of Bozen-Bolzano, 2025/26.

📄 [Отчёт по проекту (PDF)](docs/NLP_project_for_Foppa.pdf) · 📊 [Презентация (PPTX)](docs/project_nlp.pptx)

## Задача
Foppa GmbH — оптовый поставщик продуктов в Южном Тироле. Клиенты присылают заказы в свободной форме: сообщения в WhatsApp, фото рукописных списков, сканы PDF, факсовые бланки. Бэк-офис вручную переводит их в позиции ERP: точный код товара, единица измерения, количество.

Цель прототипа — принять такой заказ в любом формате и вернуть готовый к загрузке в ERP JSON, где спорные позиции подсвечены для проверки человеком.

## Как работает
1. **Извлечение (Gemini 2.5 Flash).** Текст, PDF или изображение обрабатываются одним мультимодальным вызовом и превращаются в структурированный JSON: позиции, количества, единицы, отдельно — примечания о доставке. Для каждого типа входа используется свой промпт (`app/gemini_pipeline.py`).
2. **Сопоставление с каталогом в три стадии** (`app/matching.py`):
   - поиск по шаблону клиента — 50–100 позиций, которые он заказывал раньше, вместо полного каталога на 6 460 товаров, плюс бонус за частоту;
   - нечёткое сравнение через rapidfuzz (`token_set_ratio`, `token_sort_ratio`, `partial_ratio`) с нормализацией умляутов, разбиением немецких составных слов и словарём синонимов (немецкий, итальянский, английский);
   - фолбэк по полному каталогу, если лучший результат ниже порога уверенности (по умолчанию 85); он заменяет предыдущий матч только при более высоком score.
3. **Проверка человеком.** Веб-интерфейс (`frontend/`) показывает позиции, коды, score и альтернативы; позиции ниже порога подсвечиваются. Порог регулируется слайдером.
4. **Обратная связь.** Подтверждённые заказы сохраняются в SQLite — основа для будущего обучения матчера.

## Стек
FastAPI, Pydantic, Google Gemini API (`google-genai`), rapidfuzz, pandas + openpyxl, SQLite, pytest, ванильный JS + HTML/CSS для интерфейса.

## Структура
```
foppa-order-processing/
├── app.py                   # запуск uvicorn
├── app/
│   ├── main.py              # FastAPI: /extract, /feedback
│   ├── gemini_pipeline.py   # промпты и вызов Gemini
│   ├── matching.py          # трёхстадийный матчинг, нормализация, синонимы
│   ├── sample_data.py       # демо-каталог и загрузчики реальных данных
│   └── schemas.py           # Pydantic-модели
├── frontend/                # интерфейс проверки заказа
├── tests/                   # pytest на матчинг и нормализацию
└── docs/                    # отчёт и презентация
```

## Данные
В репозитории лежит только демо-каталог из `app/sample_data.py` — на нём работают тесты и локальный запуск. Реальные файлы Foppa (каталог на 6 460 позиций и шаблоны заказов клиентов) не публикуются: код подхватывает их из `data/masterdata/` при `USE_REAL_DATA=true`.

## Как запустить
```bash
pip install -r requirements.txt
cp .env.example .env     # вписать GEMINI_API_KEY
python app.py            # http://127.0.0.1:8000
pytest                   # тесты матчинга
```

## Ограничения
- Прототип, а не продакшен: интеграции с ERP нет, результат отдаётся как JSON для ручной проверки.
- Качество извлечения на рукописных и размытых фото зависит от модели и не измерялось на отдельной размеченной выборке.
- Порог уверенности 85 подобран эмпирически.
